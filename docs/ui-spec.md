# 界面规范

这份文件是界面的唯一依据。设计稿（本地 `design/`，未入库）负责讨论和演示，
**规范以这里为准** —— 设计稿里的取值凡是与这里冲突的，都是它成稿时还没拿到实车截图。

改界面之前先读这一页；改完对照「合规现状」那一节更新它。

---

## 一、统一骨架：五个区

界面内容可以完全不同，但这五个区的位置、尺寸、含义不变。这就是「风格统一」的落点。

| 区 | 尺寸 | 内容 |
|---|---|---|
| ① 标题区 | `title_bar_height` = 64dp | 左起：**菜单或返回**（永远在这个位置）· 界面名 · 右侧本界面的一两个动作 |
| ② 列表栏 | `list_width` = 280dp | 设置的分区、配置编辑的相机、回看的日期。**左侧选、右侧改** |
| ③ 内容区 | 剩余宽度 | 各界面自己做主。规则只有一条：**一屏之内看完一件事**，放不下就该拆 |
| ④ 动作栏 | `rail_width` = 380dp（三路布局也用这一档：收窄到 300dp 时英文放不下） | 这个界面能做的事，按重要性从上往下。**主操作只有一个**。左右舵镜像到另一侧，其余四个区不动。主界面上「鱼眼校正」下面那块空处可以放**车辆状态面板**（设置 → 界面，试验性，默认关；`ui/VehicleStatusPanel`，图标和信息条同一套） |
| ⑤ 状态条 | `status_bar_height` = 48dp | 录制状态 · 存储余量 · 当前流尺寸。写的是**现在**的设置和状态，所以只放在「现在」的界面上（主界面、设置）。**内容是画面的界面上，它压在画面底边**（见下） |

### 每个界面用哪几个区

| 界面 | 区 |
|---|---|
| 主界面 | ③ ④ ⑤ |（① 拆掉了，见下）
| 设置 | ① ② ③ ⑤ |
| 配置编辑 | ① ② ③ ④ |
| 照片回放 | ① ② ③ |
| 录像回放 | ① ② ③ |
| 诊断 / 关于 | ① ③ |

> 录像回放原来有 ⑤，2026-10-01 按项目拥有者的决定拿掉：状态条写的是现在的帧率、码率档和 U 盘余量，
> 压在一段旧录像上，看的人会当成这段录像的参数（录完改过设置就对不上）。
>
> 设计稿那张表把录像回放写成 ①③④⑤，漏了 ②。它有一条连续录制的列表，
> 而 ② 的定义里本来就写着「回看的日期」—— 以本表为准。

### 主界面为什么没有 ① 标题区

那一条 64dp 里只有三样东西，每一样都有更该待的地方：

- **菜单键** 浮在画面左上角。尺寸和间距和其他界面 ① 里那个<b>同一组数</b>：
  48dp 的图标键、左 10dp、上 8dp（其他界面是在 64dp 里垂直居中，正好也是 8dp）。
  唯一的差别是量的起点 —— 那边从卡片边量，这边从画面边量。卡片的左上角不能用：
  左舵时动作栏就在那里。规范里「菜单或返回永远在最左」说的是位置关系，
  不是必须有一条横栏托着它。
  所以画面角标不占左上角：三路布局的「环视」在那一块的右上角，四宫格里落在菜单键
  底下的那一格角标往右让开。
- **应用名** 归到 ④ 动作栏顶上。那一列本来就是「这个界面能做的事」，名字挂在最上面
  不占画面。
- **配置名**（「极氪7X（环视 + 后座舱）」）归到 ⑤ 状态条。它本来就是一条「现在按什么在跑」
  的状态，和帧率、码率同类。

换来的是画面高 64dp。这块屏幕上，内容就是画面本身 —— 和 ④ 在回看界面上被否掉、
⑤ 改成压在画面上，是同一条理由的第三次应用。

其他界面（设置、回看、诊断、关于）的 ① 照旧：那里内容是文字和列表，一条标题栏
不和内容抢地方。

### ⑤ 什么时候占一行，什么时候压在画面上

**内容是画面的界面（主界面）：压在画面底边**，半透明渐变底、固定浅色字，
不占版面高度。**内容是文字或列表的界面（设置）：占一行**，贴在页面底部，跟日夜配色走。

理由和 ④ 在回看界面上被否掉是同一条：这块屏幕上，内容就是画面本身。占一行要花掉
48dp 的高度，而这条信息（帧率档、剩余空间；分段进度在录制键外圈上，状态条不重复）扫一眼就够，不需要一块独立版面。
录像回放当初也压在画面上（0.43.0 占一行时把播放控制往下挤），2026-10-01 整条拿掉，理由见上。

同一份 `layout_status_bar` 两种用法，差别由 `StatusLine.overlay()` 在代码里加上 ——
深色渐变和固定浅色字只在画面上成立，铺到设置界面就是一条莫名其妙的黑边。

### 回看界面为什么没有 ④ 动作栏

0.43.0 试过：两个回看界面的动作（刷新、多选、主页）放进右侧动作栏。实车判定不合适，
已回退到 ① 标题区右侧 —— 理由是**空间代价**：回看界面的内容就是画面本身，
动作栏要吃掉 380dp，而标题区右侧（界面名右边）本来就空着，那几个动作放得下。

动作栏对主界面是对的（那里的动作是这个界面存在的理由，值得占一列），
对回看界面不是。规范因此分界面而定，不是一刀切。

两个界面的动作组仍然是**同一份布局**（`layout_playback_actions.xml`），
换位置不等于允许各写一份。

### 录像回放为什么还是独立 Activity

设计稿上写着「要并进来」。查过代码之后决定**不并**：

- 进程本来就是同一个（清单里没有 `android:process`），并进来不改变任何进程层面的事；
- 保护录制的是 `CameraForegroundService`，不是哪个界面在最上面；
- 但现在这个独立 Activity **白拿了一个好处**：打开它时主界面 `onPause`，
  没在录制就会主动关掉所有相机，播放器于是拿到完整的解码和内存预算。
  并进来之后主界面一直是 resumed，要恢复这个行为就得自己写一套
  「进回看关相机、但正在录制时不关」的逻辑 —— 写错就是预览和播放抢解码器，
  而这台车机的解码路数有限，这个项目在这上面栽过。

所以它保持独立，但缺的 ④⑤ 要补齐。

## 二、取值

**全部写在 `values/` 里，代码和布局只引用名字。** 布局里不许再出现字面 sp、颜色值。

### 尺寸（`dimens.xml`）

`title_bar_height` 64dp · `status_bar_height` 48dp · `list_width` 280dp ·
`rail_width` 380dp · `corner_radius` 10dp ·
`gutter` 12dp · `icon_button_size` 48dp

> 设计稿上写的是 `list_width` 360dp、圆角 16dp。那是拿到实车截图之前的草案，
> 稿子里自己写着「等给了 Zeekr OS 的比例再对齐」。现在这两个数按实车截图取：
> 左栏约占屏宽 16%，卡片圆角约 10dp。**以本节为准。**

### 字号（`type.xml`）

五档，布局里写 `android:textAppearance`，不写 `android:textSize`：

| 档 | 值 | 用在 |
|---|---|---|
| `TextAppearance.Cam.Micro` | 16sp | 角标、计数 |
| `TextAppearance.Cam.Caption` | 20sp | 说明、状态条、画面角标 |
| `TextAppearance.Cam.Body` | 22sp | 正文、按钮文字 |
| `TextAppearance.Cam.Row` | 24sp | 列表行标题、分区标题、对话框正文 |
| `TextAppearance.Cam.Title` | 32sp | 页面标题、对话框标题 |

**怎么取的值**（项目所有者 2026-10-23）：0.41.0 那一套（14 / 16 / 18 / 21 / 26）放大约 1.2 倍，
取最近的常用字号 —— 偶数，24 以内每 2 一档、再往上每 4 一档（12、14、16、18、20、22、24、28、32、36…）。
最小一档算出来 16.8，取 16 不取 18，和下一档 20 拉得开。主界面和设置回到 2.14 及以前的大小（每档差 1sp 左右），
录像回放、照片回放、诊断信息、关于以前没放大过，这次一起变大。原来的第六档 Display（28sp，计时、张数）没有地方用，去掉了。

**所有界面共用这一张表**：主界面、设置、录像回放、照片回放、诊断信息、关于、对话框。
悬浮按钮（字号在它自己的设置里）、超级镜子和盲区画面（字跟着窗口大小算）不走这张表。

**设置界面整体低一档**（行标题用 Body、说明用 Micro）：它是停着读的密集列表，
一屏十几行，按开车时瞟一眼的尺寸排会挤满整屏。

`TypeScaleTest` 钉住这条，开发者工具的布局不在其列。

**界面上显示的就是表里的值，不另外整体放大。** EVCam 留下的主界面字号 1.2 倍已去掉（项目所有者 2026-10-20）。
字要调大调小，先改这张表，再照表改界面。

### 颜色（`colors.xml` / `values-night/colors.xml`）

十个语义名，日夜各一份、同名同数量，`ColorResourceParityTest` 钉住：

`bg` · `surface` · `sunken` · `line` · `text_primary` · `text_secondary` ·
`text_tertiary` · `energy` · `energy_quiet` · `recording`

四条用色规则：

1. **能量色（极氪橙）不写字。** 它够做填充和指示，不够做文字；要写成橙色文字用 `energy_text`。
2. **一屏最多一处能量色。** 当前选中、或正在进行，二选一。两处以上就没有「跳出来」这回事。
3. **红色只标录制。** `recording` 只用于「正在录」和不可逆操作（删除、恢复初值）。
   按钮整块变红等于把「这个按钮」和「正在录」混为一谈。
4. **层次靠明度，不靠阴影。** 车机屏大、视距远，阴影只会糊；用 1px 分隔线和相邻明度分层。

## 三、控件

全用平台自带的，不引新库、不自绘：

- **对话框**：只有一条路 —— `MaterialAlertDialogBuilder` + `Theme.Cam.MaterialAlertDialog`，
  经 `CamDialogs` 弹出（它在显示那一刻把按钮画好）。框架的 `android.app.AlertDialog`
  在实车上**整条按钮栏不显示**，`DialogStyleTest` 钉住这条。
- **设置行**：`PreferenceRows` 按类型套布局（`pref_row*`），开关在行首、值在行尾。
  - **开关加下一层**（`SwitchNavPreference`，项目所有者 2026-10-23）：一个功能既要开关、又要到下一层去填写或选择时，
    合成一行（车牌号水印、行驶信息条）。行首的开关只管开关；点这一行其余的地方进下一层（输入框或页面）；
    行尾写当前值（车牌号、选了几项）再加 ›。还没填就打开的（车牌号还空着），先弹输入框，填了才算打开。
    和安卓系统设置里 Wi-Fi、蓝牙那一行是同一种（点字进详情、点开关只开关），开关照车机放在行首。
  - **开关加附加项**（`SwitchChipsPreference`，项目所有者 2026-10-23）：一个功能开着时还有几样可以单独开、关的附加项，
    合成一行（锁定影像 + 自动锁定的「闪远光」「鸣笛」）。行首的开关管整个功能，点这一行也是它（没有下一层）；行尾写当前值；
    开着时说明下面多一排：小标题（「自动锁定」）加按钮（Material 的筛选按钮 `Chip`，按下是开、再按是关；
    开是橙色淡底 + 橙描边 + 橙字 + 勾，关是中性灰块，高 48dp），关着时那一排不显示。
    还不能用的附加项照样摆出来，置灰、按不动（鸣笛：车机还读不到喇叭信号，项目所有者 2026-10-23）。
  - **说明放进下一层，写在下面**：只读的说明、路径不单独占一行，放进相关的那个框里（选盘之前要知道的写在选盘的框里）。
    框里的说明是次要的（项目所有者 2026-10-23）：写在选项、输入框**下面**，小一号（Caption）、次要文字色，
    和 Material 输入框下面那行帮助文字一个位置（`CamDialogs.note`）；标题下面只写此刻的状态（选盘框：录像保存在哪）。
    对话框自带的正文（`setMessage`）只给确认框用 —— 那里正文就是要问的事。
- **开关**：滑块永远白，打开时轨道是橙色。没有「浅橙轨道」这一档。
- **动作栏**：`layout_action_rail.xml`，各主界面 `<include>` 进去。主界面没有四宫格键 ——点画面里的一格就放大到整块预览区（填充），再点还原；座舱那两路同理。回看两键下面是「鱼眼校正」（临时位置，试效果用），和照片回放、录像回放标题区里那个是同一个开关（`FisheyeToggleButton`）。右下角是「隐藏到后台」，长按退出；抽屉和设置左栏的最底下也有退出。
- **图标**：矢量图，16/20/24dp 网格，一套线条风格。**不用字符图标**（☰ ⌂ 这类）。

## 四、三条原则

1. **固定的东西不许移动** —— 菜单、返回、录制，在每个界面都在同一个坐标。
2. **横向用满，纵向省着用** —— 能并排就不要堆叠；一屏之内看完一件事。
   车机是坐着够不着、停车时用的屏：手要伸出去，滚动比点击贵得多。
3. **可见性不能依赖主题解析** —— 按钮自己画，不赌主题属性能解析出想要的结果。

## 六、多份布局副本

同一个界面**只能有一份布局**。

`layout-sw600dp/`、`layout-port/` 这类变体目录曾经存在，结果是：车机屏走的是
`sw600dp` 那一份，而重做只做在了 `layout/` 上 —— 界面改了四个月，车上一直显示旧版，
副本里还留着写死的中文。0.42.0 把它们全删了。

要做屏幕适配，用 `dimens.xml` 里的限定符或布局本身的权重，不要整份复制。

## 七、录像回放：进度条跟着环视

项目拥有者 2026-10-10 定。一路摄像头被其他应用占用时只停该路、其余照录，释放后该路单独接回 ——
同一次录制里各路的录像于是不再一样长，回放按下面几条走：

- **进度条按环视排，也跟着环视走。** 长度、位置、哪几段算一条录制都只看环视；座舱晚开头、
  中间缺一段、提前结束，都不改变进度条。
- **座舱此时没有录像**：网格里该格写「该路此时无录像」，点它不放大，底部的切换按钮也跳过它。
  放大着的座舱放到没有录像的地方、拖到没有录像的地方、或者文件无法播放，都收回网格，
  环视从那一刻接着放 —— 进度条不跳过环视的录像，也不停在半路。
  空 5 秒以内算接着的（`RecordingTimeline.DEFAULT_MAX_GAP_MS`，和环视判断「同一次录制」同一个数）；
  座舱比环视早结束不到 5 秒，算这一条放完。
- **环视之外的座舱录像**（环视停着、或者还没加入时座舱录下的）**存着，但不放**：放大的座舱放到环视的末尾就停。
  每个文件至多归一条录制，归时间上离它最近的那一条（2026-10-11）：和哪一条重叠就归哪一条（跨着两条的归重叠得多的那条）；
  不重叠的归隔得最近的那一条，一样近归前一条，但最多隔这一路的一个分段时长；再远的不归任何一条。
  以前归「开头之前（往前放宽 5 秒）最近开录的那一条」、没有上限：环视加入之前座舱录的那几段会挂到上一条录制上，可能是前一天的，
  删前一天那条时跟着被删掉。
  删除、分享、大小、列表里的「含已锁定文件」都按「归哪条」算，锁定的照旧留下。画面上放哪些则按时间重叠算，
  一个文件可以在相邻两条里都露面。
- **锁定 / 解锁碰的是「此刻」那一批**（2026-10-11）：画面上此刻各路正在放的文件，加上挂在此刻环视那一段上的、环视之外的座舱文件 ——
  同一条录制里时间上离它最近的那一段环视，一样近挂前一段。按钮上写「锁定」还是「解锁」也按这一批。
  进度条下的锁定细条画归这一条的文件（环视之外的那几个正好落在它挂靠的那一段的一端，成一个点 —— 放到那一段按「锁定 / 解锁」，碰的就有它）
  和画面上露面的文件。
  以前整个在环视之外的座舱文件不在任何时刻的画面上，锁不上，锁着的也解不开。
- 已知的缺口：离哪一条环视录制都超过一个分段时长的座舱文件不归任何一条 —— 回放里删不掉、锁不到，只由循环清理收；
  要不要给它们单独一条，以后再定。

实现：`PlaybackLead`（谁领头）、`LaneTrack.shownIn` / `belongingTo` / `byRecording` / `attachedTo`（放哪些 / 归哪条 / 挂哪一段），
都有单元测试（`LaneTrackTest`、`LaneTrackAttachTest`、`PlaybackLeadTest`）。

## 八、录像此刻的样子：录制键、悬浮按钮、通知（2.11）

项目拥有者 2026-10-10 定：录像每一路各自进出，所有路都暂时录不了时录像不算停（lifecycle-spec 2.5）。
于是录像开着时有三个样子，三处照同一个答案画（`RecordingCoordinator.view`），不各自猜：

| 样子 | 什么时候 | 录制键 | 悬浮按钮 | 前台通知标题 |
|---|---|---|---|---|
| 准备中 | 这次录像还没离开过「准备中」，一路都没在录，有一路在起来 | 方块一明一暗地呼吸，环在转；「正在准备…」 | 同在录 | 「正在录制」 |
| 在录 | 至少一路在录 | 方块，环按本段已录的比例走；「停止录制」+ 本段进度 | 录制红的方块 + 本段进度 + 时长 | 「正在录制」 |
| 等待摄像头 | 一路都没在录：被占用、在救、救了 3 轮停手、现在用不了相机，或者录制器建不起来 | 灰色方块慢慢地一明一暗（比准备中慢得多），环不转、不走，不显示本段时长；「等待摄像头」/「恢复后自动继续」 | 灰环、灰方块，没有进度弧，不显示时长 | 「等待摄像头，恢复后自动继续」 |

- **红色只标「正在录」**（二、颜色第 3 条）：等待摄像头时录像开着，但一路都没在录，点和环都是灰的（`text_tertiary`）。
- **按下去仍然是停止录制**：等待摄像头时录像意图开着，录制键的内容描述照旧是「停止录制」，悬浮按钮按一下也是停。
- **熄屏提示那一行**（录制键第三行，lifecycle-spec 2.4）在录和等待摄像头时都显示：录像开着，熄屏的话这段录像会怎样照常说。
  2.11.2 起三句：「熄屏后继续录制环视」「熄屏暂停，亮屏后恢复」「熄屏后停止录制」，
  照协调器同一张表判熄屏那一刻和之后车机要睡那一刻（项目所有者 2026-10-13：要说清车机休眠时还录不录）——「熄屏持续录制」、
  开发者「熄屏录制」（和它的唤醒锁）、「启动自动录制」、这一次录像里有没有环视、哨兵模式、挡位。熄屏接着录、车机要睡也接着录
  （哨兵模式开着、在开车、唤醒锁拉着）是第一句；车机要睡时停（哨兵模式没开：环视录到车机休眠）也写第二句「熄屏暂停，亮屏后恢复」
  （项目所有者 2026-10-13 定，不另加句子；「熄屏续录需开启哨兵模式」删了）。
  车辆信号判不出屏幕时（降级：熄屏就是车机下电，两下是同一下）熄屏持续录制开着而哨兵模式没开，写「熄屏暂停，亮屏后恢复」。
  看得见时听车辆信号的连接和读数（只听，不开浮点和定位；哨兵模式、挡位是核心一直在读的），这几样变了就跟着变。
- **熄屏是屏幕真黑了**（2.11.2，lifecycle-spec 2.4）：车主下车、中控屏一黑，主界面就按熄屏处理（不再等几分钟后车机下电）——
  熄屏那一刻在前就记下「因熄屏退下去」，15 秒后退到后台并提示「熄屏 15 秒，已转入后台」（在录、等待摄像头、在等开录、开发者「熄屏录制」开着时不退），
  开车门亮屏时接回前台；熄屏 15 秒那一步到点时屏幕黑没黑还不知道（安卓刚亮、车辆信号还没读回来）就过 2 秒再看。
- **主界面状态条**只在录的时候说哪一路被占用、哪一路无法录制（lifecycle-spec 2.5）；等待摄像头时由录制键说。
- 开录落定那一下的提示按真正在录的几路说；一路都没在录就是「等待摄像头，恢复后自动继续」。
- **各路都停手时不加新文字**（项目拥有者 2026-10-11 定）：仍然是「等待摄像头」「恢复后自动继续」——
  停手的一路在亮屏、相机服务报它空闲时从头再试，这句话仍然属实。
- **现在用不了相机**（主界面不在前、前台服务是后台起的）也是「恢复后自动继续」：屏幕亮着时，开录、接回的那一下录像协调器先把主界面拉起来
  （闪一下退后台，lifecycle-spec 2.4、§3.5「能用相机」），它一起来相机就开得起来，不用人自己打开主界面（2.11 审查 2026-10-11）。
  屏幕黑着一律不拉（项目所有者 2026-10-13）：黑着时照表开起来的录像用不了相机就「等待摄像头」，亮屏那一下协调器再判、该拉就拉。
  屏幕亮着、已经在录时才变成用不了的（录着时前台服务在后台被系统重启）不拉，等主界面回到前台或下一次亮屏 —— 很少见，记在 lifecycle-spec 2.4。
- 前台通知在后台时只换字（`NotificationManager`），不为换字去起服务；主界面回到前台刷新服务时照此刻的样子写。
- 文字照 `ui-text-style.md`，三种语言同一句话：「等待摄像头」「恢复后自动继续」「等待摄像头，恢复后自动继续」。

实现：`RecordingLanes.summarize`（各路的样子 → 整体的样子，有单元测试）、`RecordButtonUi.State.WAITING`、
`RecordingFloatingService`（`setRecording(recording, waiting)`）、`RecordingCoordinator.notificationTitle`。

## 九、盲区画面：中控屏和 HUD（2026-10-21）

项目所有者 2026-10-21 定：直接用 FerixzTanz（CAMCORDER）的 HUD 做法和设置，照我们现在的结构做。盲区画面于是有两个出口，
**一套判定**（`SideViewTrigger`）、**一个画面**（`SideViewPicture`：拉直、往后看、每次显示先盖黑、新帧停了也盖上），只是窗口不同。

| | 中控屏 | HUD |
|---|---|---|
| 窗口 | 悬浮窗（`SideViewWindow`），固定大小位置（屏高 33%、宽 ÷ 高 2.2，左右各一个） | HUD 那块屏上的透明 Presentation（`SideViewHudWindow`），大小位置照设置 |
| 显示规则 | 左灯左侧、右灯右侧；灯灭 1 秒后收；D 挡备着；离开 D 挡 30 秒移走；熄屏、原厂画面（倒挡、原厂 360、原厂小窗、泊车辅助）全收 | 同左，**不看最低车速**（FerixzTanz 的规则，项目所有者 2026-10-16 定照用） |
| 操作 | 右上角一个关闭按钮，关掉这一次打灯（两处一起收） | 不接点击、没有按钮（HUD 不是触摸屏） |
| 镜像 | 不镜像（项目所有者 2026-10-16） | 「左右翻转」，默认开（FerixzTanz 的设置），方向和车外后视镜一致 |
| 样子 | 原画面 | 对比度曲线（白天 220%、夜间 100%）、四边渐隐（短边的 6%）、透明度（100%）、夜间亮度（100%）：HUD 是投影，黑色是不亮 |

- **显示位置**（设置 → 超级镜子 → 盲区画面 →「显示位置」，分段三档）：中控屏 / HUD / 中控屏和 HUD，默认两处（FerixzTanz 的设置）。
  选 HUD 而找不到 HUD 那块屏、或者这一段 HUD 用不了（窗口挂不上、相机层不带它）时，退回中控屏。
- **哪块屏是 HUD**（`HudScreen`）：不是主屏、真实尺寸 1440×480（7X 上是 id 3）；没有就退到 id 3，但不能是 2560×536（仪表盘）；关着的屏不算。
  诊断报告「显示屏」一节写出找到了哪一块、怎么找到的，以及 HUD 窗口此刻的样子。
- **HUD 上的位置大小**（`HudPicture.place`）：高度是 HUD 高的百分比，宽 = 高 × 形状；左灯离左边、右灯离右边，
  是剩余宽度的百分比（0 贴边、50 居中）；上下是剩余高度的百分比（0 最上、100 最下）。
- **设置**（「HUD 画面」一组，显示位置是「中控屏」时整组不可用；数值行显示的就是实际用的数）：

  | 行 | 范围 | 默认 |
  |---|---|---|
  | 左右翻转 | 开 / 关 | 开 |
  | 画面高度 | 30–100 | 49 |
  | 画面形状 | 100–300 | 194 |
  | 离边距离 | 0–100 | 11 |
  | 上下位置 | 0–100 | 21 |
  | 画面透明度 | 20–100 | 100 |
  | 白天对比度 | 100–300 | 220 |
  | 夜间对比度 | 100–300 | 100 |
  | 夜间亮度 | 20–100 | 100 |
  | 边缘渐隐 | 0–40 | 6 |

  默认值是 FerixzTanz 在他 7X 上调出来的（1440×480 上画面 456×235，离边约 108 px）；「最低车速」只管中控屏。
  拉直、视野、朝向两处共用（开发者选项里的三个标定角度）。
- **相机**：HUD 的画布是环视的另一样输出（`ChannelRules.Kind.HUD`），和预览、超级镜子、中控屏的盲区画面挂在同一条共享预览流上
  （四块正好是 AOSP 的上限 4），跟同一个登记方（SIDE_VIEW）。挂不下时 HUD 那块排在最后、先让路；会话配不上时两块盲区画面一起先丢（JPEG 之后）。

实现：`SideViewService`（两个出口 `Output`）、`SideViewWindow`、`SideViewHudWindow`、`SideViewPicture`、`HudScreen`、`HudPicture`，
纯逻辑有单元测试（`HudScreenTest`、`HudPictureTest`、`ChannelRulesTest.theHudCanvasFollowsTheSideViewHolder`）。
